# هيا لايف (Hayya Live) — مشروع تخرج Flutter

تطبيق لعرض جداول ونتائج المباريات وتفاصيلها (على غرار يلا شوت / 360)، مبني بـ Flutter وقاعدة بيانات SQLite محلية.

---

## 1) خطوات التشغيل من الصفر (النسخة النهائية: أندرويد + iOS + Chrome)

**الطريقة الأسهل والأضمن (ويندوز):** بعد فك الضغط، **اضغط دبل-كليك على ملف `run_setup.bat`** الموجود في مجلد المشروع — ينفّذ لك كل خطوات الإعداد تلقائيًا (توليد ملفات android/ios/web + تنزيل الحزم) ويمنع تكرار مشكلة "AndroidManifest.xml مفقود".

إذا تفضّل التنفيذ اليدوي، أو كنت على Mac (لبناء iOS، استخدم `run_setup.sh`):

1. افتح Terminal داخل مجلد المشروع `hayya_live`.
2. نفّذ:
   ```
   flutter create .
   flutter pub get
   ```
   هذا يولّد مجلدات android و ios و web تلقائيًا **دون المساس بأي كود موجود في lib/**.
3. **إعداد إرسال البريد الإلكتروني الحقيقي (خطوة إلزامية لبند نسيان كلمة المرور):**
   1. فعّل "التحقق بخطوتين" (2-Step Verification) في حساب Gmail من: `myaccount.google.com/security`
   2. اذهب إلى `myaccount.google.com/apppasswords` وأنشئ App Password (16 حرفًا)
   3. افتح `lib/services/email_service.dart` واستبدل `YOUR_EMAIL@gmail.com` و`YOUR_16_CHAR_APP_PASSWORD` ببياناتك (بدون مسافات في الرمز)
4. **التشغيل على أندرويد (الطريقة المطلوبة للتقييم حسب الدكتور):**
   - وصّل جوالك بالكيبل وفعّل "خيارات المطور" ثم "تصحيح USB" (USB Debugging)، أو شغّل محاكي من Device Manager
   - من قائمة الأجهزة بجانب زر Run اختر جهازك/المحاكي (**وليس Chrome ولا Windows**) واضغط Run
5. **التشغيل على iOS (يتطلب جهاز Mac مع Xcode):**
   - انقل المشروع لجهاز Mac، نفّذ نفس خطوتي 2 و3 هناك، ثم شغّل على iOS Simulator أو آيفون حقيقي
6. **التشغيل على Chrome (اختياري، غير مطلوب للتقييم لكن يعمل الآن):**
   ```
   dart run sqflite_common_ffi_web:setup
   flutter run -d chrome
   ```
   ⚠️ دعم SQLite على الويب لا يزال تجريبيًا حسب توثيق الحزمة نفسها — إذا واجهت أي عطل غير متوقع، اعتمد على أندرويد فقط للمناقشة (هو ما يطلبه الدكتور فعليًا).
7. لإنشاء APK قابل للتشغيل (متطلب رقم 14):
   ```
   flutter build apk --release
   ```
   الملف الناتج: `build/app/outputs/flutter-apk/app-release.apk`

> ملاحظة: يحتاج التطبيق اتصال إنترنت لعرض شعارات الفرق/البطولات ولإرسال بريد OTP.

## 3) قائمة الملفات ووظيفة كل ملف

- `lib/main.dart` — نقطة البداية، إعداد الثيم واتجاه RTL
- `lib/models/*.dart` — نماذج البيانات (User, Competition, Match, Favorite)
- `lib/database/db_helper.dart` — كل التعامل مع SQLite (إنشاء الجداول وعمليات CRUD)
- `lib/services/email_service.dart` — إرسال رمز OTP الحقيقي عبر بريد Gmail (SMTP)
- `lib/screens/login_screen.dart` — تسجيل الدخول
- `lib/screens/register_screen.dart` — إنشاء حساب
- `lib/screens/forgot_password_screen.dart` — استعادة كلمة المرور (3 مراحل)
- `lib/screens/main_navigation_screen.dart` — الحاوية الرئيسية وشريط التنقل السفلي
- `lib/screens/home_screen.dart` — مباريات اليوم + إحصائيات
- `lib/screens/competitions_screen.dart` — شبكة البطولات
- `lib/screens/all_matches_screen.dart` — كل المباريات مع فلترة
- `lib/screens/favorites_screen.dart` — المباريات المفضلة
- `lib/screens/profile_screen.dart` — بيانات المستخدم وتسجيل الخروج
- `lib/screens/match_details_screen.dart` — تفاصيل مباراة + تعديل/حذف/مفضلة
- `lib/screens/add_edit_match_screen.dart` — نموذج إضافة/تعديل مباراة
- `lib/widgets/match_card.dart` — بطاقة مباراة قابلة لإعادة الاستخدام
- `lib/widgets/stat_card.dart` — بطاقة إحصائية قابلة لإعادة الاستخدام

## 4) الحزم (Packages) المستخدمة

| Package | السبب |
|---|---|
| `sqflite` | التعامل مع قاعدة بيانات SQLite المحلية (أندرويد/iOS) |
| `sqflite_common_ffi_web` | لتشغيل نفس قاعدة SQLite على متصفح Chrome (عبر WASM) - اختياري، غير مطلوب للتقييم |
| `mailer` | إرسال رمز OTP الحقيقي إلى بريد المستخدم عبر SMTP (Gmail) عند نسيان كلمة المرور |
| `path` | تحديد مسار ملف قاعدة البيانات على الجهاز |

لا توجد أي حزمة أخرى — كل شيء آخر (التاريخ/الوقت، الصور، الفورمات) نُفّذ بالأدوات الأساسية في Flutter.

## 5) مشاكل محتملة وحلولها

- **"AndroidManifest.xml could not be found" عند التشغيل:** معناها أن `flutter create .` لم يُنفَّذ في مجلد المشروع. شغّل `run_setup.bat` (أو نفّذ `flutter create .` يدويًا) وتأكد من ظهور مجلد `android` بجانب `lib` في قائمة الملفات قبل الضغط على Run.
- **رسالة "تعذّر إرسال البريد الإلكتروني" عند نسيان كلمة المرور:** تأكد أنك استبدلت `YOUR_EMAIL@gmail.com` و`YOUR_16_CHAR_APP_PASSWORD` في `lib/services/email_service.dart` ببياناتك الفعلية، وأن "التحقق بخطوتين" مفعّل على حساب Gmail المستخدم، وأن الجهاز متصل بالإنترنت.
- **الرسالة تصل لمجلد الرسائل غير المرغوبة (Spam):** طبيعي أحيانًا مع حسابات Gmail الجديدة، تحقق من هذا المجلد عند الاختبار.
- **الصور لا تظهر:** يحتاج الجهاز/المحاكي اتصال إنترنت لأن الشعارات تُحمّل من الإنترنت (Image.network). في حال انعدام الإنترنت ستظهر أيقونة بديلة تلقائيًا (تم التعامل مع هذا عبر errorBuilder).
- **خطأ عند `flutter create .`:** تأكد أن Flutter SDK مثبت ومُضاف لـ PATH (`flutter doctor` للتأكد).
- **قاعدة بيانات فارغة بعد أول تشغيل:** طبيعي، البطولتان الافتراضيتان تُضافان تلقائيًا، لكن المباريات يجب إضافتها يدويًا من زر (+) في الشاشة الرئيسية.
- **لا تظهر مباريات في "مباريات اليوم":** لأن التاريخ الافتراضي عند الإضافة هو تاريخ اليوم فقط إذا اخترته من منتقي التاريخ؛ تأكد من اختيار تاريخ اليوم عند إضافة مباراة تجريبية، أو تفقدها من شاشة "كل المباريات".

## 6) سيناريو اختبار بسيط لكل وظيفة أساسية

1. **التسجيل:** أنشئ حسابًا ببريد غير صحيح (بدون @) → يجب أن تظهر رسالة خطأ.
2. **الدخول:** سجّل دخول ببيانات صحيحة → يجب الانتقال للشاشة الرئيسية.
3. **نسيت كلمة المرور:** اضغط الرابط، أدخل بريدك، تحقق من صندوق الوارد (أو Spam) لرؤية رمز OTP الحقيقي المرسل، أدخل رمزًا خاطئًا (تظهر رسالة فشل)، ثم أدخل الرمز الصحيح (ينتقل لشاشة كلمة المرور الجديدة).
4. **إضافة مباراة:** من الشاشة الرئيسية اضغط (+)، أدخل بيانات مباراة بتاريخ اليوم واحفظ → يجب أن تظهر في "مباريات اليوم" فورًا.
5. **تعديل/حذف:** افتح المباراة، عدّل النتيجة واحفظ، ثم جرّب حذفها (مع تأكيد الحذف عبر Dialog).
6. **المفضلة:** أضف مباراة للمفضلة بالنجمة، تحقق من ظهورها في شاشة "المفضلة"، ثم أزلها.
7. **إغلاق التطبيق وإعادة فتحه:** تأكد أن المباريات المُضافة ما زالت موجودة (دليل الحفظ الفعلي في SQLite).

## 7) أسئلة مناقشة متوقعة من الدكتور

**س: لماذا اخترت SQLite ولم تستخدم Firebase أو API؟**
ج: المشروع محلي بالكامل بدون خادم، وSQLite هي الحل القياسي المدمج في Flutter لتخزين البيانات محليًا بشكل دائم، وهي مناسبة تمامًا لحجم ونطاق مشروع تخرج.

**س: كيف تعمل آلية "نسيت كلمة المرور"؟**
ج: يُولَّد رمز عشوائي من 6 أرقام ويُرسل فعليًا إلى بريد المستخدم عبر خدمة SMTP الخاصة بـ Gmail (باستخدام حزمة `mailer`)، ثم يُقارَن الرمز الذي يدخله المستخدم بالرمز المُرسل؛ عند التطابق ينتقل لشاشة كلمة مرور جديدة، وعند عدم التطابق تظهر رسالة فشل واضحة.

**س: أين تُخزَّن قاعدة البيانات؟**
ج: على تخزين الجهاز نفسه (Local Storage) عبر `sqflite`، في ملف `hayya_live.db`، ويتم إنشاؤه تلقائيًا أول مرة يعمل فيها التطبيق.

**س: كيف يتم تحديث الشاشة فور إضافة/حذف مباراة دون إعادة تشغيل التطبيق؟**
ج: باستخدام `StatefulWidget` مع `setState()`: بعد كل عملية إضافة/تعديل/حذف يتم استدعاء دالة تُعيد تحميل البيانات من قاعدة البيانات وتُحدّث الواجهة تلقائيًا.

**س: لماذا لم تستخدم Provider أو Bloc لإدارة الحالة؟**
ج: حجم المشروع لا يحتاج إدارة حالة متقدمة؛ `setState` كافٍ وواضح وأسهل شرحًا، ويحقق كل المتطلبات دون تعقيد غير ضروري.

**س: من يستطيع إضافة/تعديل/حذف المباريات؟**
ج: أي مستخدم مسجّل دخول، تبسيطًا للمشروع (بدون نظام صلاحيات Admin/User منفصل)، وهذا قرار تصميمي مقصود لتحقيق البساطة المطلوبة في مشروع جامعي.
